# AGENTS.md

Ты автономный инженер проекта. Работай по циклу из `docs/03-autopilot-protocol.md`. Здесь только то, что нельзя нарушать.

## Порядок старта сессии (всегда)

1. Прочитать этот файл, затем `docs/02-code-conventions.md`.
2. Выполнить `nx run progress:resume`. Команда покажет текущую задачу, что уже сделано и следующее действие.
3. Прочитать файл эпика текущей задачи и только релевантные разделы `docs/01-architecture.md`.
4. Не начинать с нуля то, что уже сделано. Сначала `git status`, `git log -5` и `progress verify`.

## Нерушимые правила

- Один коммит затрагивает один проект Nx. Формат: `<icon> <type>: <rootScope>/<moduleScope>: <message>`.
- Перед коммитом линтинг и форматирование проходят автоматически. Не обходить хуки (`--no-verify` запрещён).
- Любой код создаётся генераторами Nx нужного типа. Структуру вручную не изобретать.
- Нативные компоненты Angular Material запрещены вне пакетов `ui-web`. Везде используем свои UI-компоненты.
- Любая строка интерфейса идёт через i18n-ключ (hy, ru, en). Захардкоженный текст запрещён.
- Деньги только целыми числами в минимальных единицах валюты вместе с кодом валюты. Тип `number` с плавающей точкой для денег запрещён.
- Секреты только в `.env` или AWS Secrets Manager, остальное в TOML. В коде и логах секретов нет.
- Любое поведение покрыто тестами. Тесты лежат в `test/` модуля, не в `src/`.
- Тип `any` запрещён (порядок: generics, затем `unknown`, затем алиас `Any` из `ts-utils`).
- Функция или тип, используемые больше одного раза, переезжают в utility-пакет.
- Задача считается выполненной только после успешного `nx run progress:verify <task-id>`. Самому ставить статус «done» нельзя.

## Если что-то неясно

Не останавливайся. Выбери вариант, который лучше всего согласуется с приоритетом документов из README, запиши допущение в `docs/decisions/assumptions.md` (id, дата, вопрос, выбранный вариант, почему) и продолжай. Останавливаться можно только если нужен внешний секрет, аккаунт или платное действие. Тогда пометь задачу `blocked`, опиши что нужно, и переходи к следующей независимой задаче.

## Контрольные точки

После каждого завершённого подшага выполнить `nx run progress:checkpoint --note "<что дальше>"`. Это обязательное условие возобновления работы после сбоя.
