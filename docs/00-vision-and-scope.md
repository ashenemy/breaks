# 00. Видение, роли, границы, журнал решений

## 1. Продукт

Мультивендор-маркетплейс строительных товаров для Армении. Услуги (ремонт, монтаж) добавляются позже, модель данных должна это допускать.
Языки интерфейса и контента: армянский (hy), русский (ru), английский (en). Валюты отображения: AMD, RUB, EUR, USD с конвертацией. Расчётная валюта платформы: AMD.
Клиенты: веб (адаптивный, SSR), мобильное приложение покупателя (Android и iOS), вендорский и админский порталы только в вебе (вендорский полностью адаптивный, с web-push).

### Отличия от обычных каталогов (главные ставки продукта)
1. ИИ-поиск по задаче: пользователь описывает работу («косметический ремонт детской»), система возвращает группы товаров по этапам.
2. Калькуляторы количества материалов по категориям.
3. Проекты (сметы): группы позиций, калькуляторы, перенос в корзину, ссылка для шаринга.
4. Кастомный инвойс из чата со ссылкой на оплату.
5. Поиск по армянскому языку высокого качества.
6. ИИ-помощник вендора для текстов и медиа, автоперевод на hy/ru/en.

## 2. Роли

| Роль | Портал | Кратко |
|---|---|---|
| Гость | web, mobile | Каталог, поиск, калькуляторы, проекты (локально, до входа) |
| Покупатель | web, mobile | Заказы, чат, отзывы, жалобы, лояльность, проекты |
| Владелец вендора | vendor | Всё в рамках своего вендора |
| Сотрудник вендора | vendor | Права по матрице «раздел × действие», готовые роли: маркетолог, менеджер заказов, склад, бухгалтер, свои роли |
| Админ платформы | admin | Все настройки |
| Модератор | admin | Вендоры, товары, отзывы, пользователи |
| Саппорт | admin | Чаты, обращения, просмотр заказов |
| Арбитр | admin | Споры и жалобы, решения влияют на выплаты |
| Бухгалтер платформы | admin | Леджер, выплаты, выгрузки |
| Логист платформы | admin | Службы доставки, назначение, контроль доставок |

Права платформы описываются той же моделью матрицы, что и права сотрудников вендора.

## 3. Глоссарий

- **Заказ (Order)**: оформление покупателя. Делится на **подзаказы (SubOrder)** по вендорам.
- **Отгрузка (Shipment)**: один рейс доставки подзаказа. Доставка «по готовности» создаёт несколько отгрузок.
- **Вариант (Variant)**: вариация товара (например цвет) со своей ценой, медиа и остатками.
- **Набор свойств (PropertyPreset)**: библиотека свойств, задаётся в админке и привязывается к категориям.
- **Кошелёк вендора**: баланс для платного размещения и ИИ-кредитов.
- **Леджер**: журнал проводок двойной записи, единственный источник правды по деньгам.

## 4. Границы

### Входит в релиз
Всё, что описано в эпиках (см. `04-roadmap.md`). Лояльность и сборка проектов входят в «простом» виде (см. журнал решений).

### Явно не входит (но архитектура не должна мешать)
- 3D-генерация (допустимо позже: загрузка GLB плюс просмотрщик).
- Viber и Telegram уведомления.
- Приложение водителя, личные кабинеты и API служб доставки.
- Мобильные приложения вендора и админа.
- Интеграции со складскими программами (на старте только CSV/Excel, но через провайдер-интерфейс).
- Полноценные B2B-аккаунты (только оплата по счёту и выгрузка данных для бухгалтерии).
- Реальные платёжные шлюзы (на старте только тестовая заглушка; интерфейс провайдера обязателен).

## 5. Журнал решений (из интервью)

| № | Решение |
|---|---|
| D-01 | Платное размещение: фиксированные слоты с пометкой «Реклама»; модели «за клик» и «за время»; оплата с кошелька вендора |
| D-02 | Платформа принимает оплату, держит до подтверждения доставки; выплата вендору настраивается по вендору (сразу или раз в период) |
| D-03 | Глобальное окно удержания на возвраты и жалобы; открытая жалоба замораживает выплату по подзаказу |
| D-04 | Доставка на аутсорсе: службы заводит админ, назначение и контроль вручную; без интеграции |
| D-05 | Калькулятор доставки: отдельные коэффициенты по службе; расстояние, вес, объём, грузчики (фикс за грузчика) |
| D-06 | Лояльность: уровни по сумме заказов, процент и пороги настраиваются, настройка «скидка с доставкой или без» |
| D-07 | Вход: телефон (OTP), Google, Facebook |
| D-08 | Уведомления: email, SMS, push; покупатель настраивает по типам событий |
| D-09 | ИИ: бесплатная квота в месяц, докупка кредитов с кошелька; провайдеры через абстракцию |
| D-10 | Чат с автопереводом hy/ru/en; кастомный инвойс со ссылкой на оплату в чате |
| D-11 | Нагрузка на запуск: ~50k MAU, ~100 RPS пик; AWS; Docker и GitHub Actions |
| D-12 | Калькуляторы на старте: краска, плитка, обои, ламинат/паркет, штукатурка/шпаклёвка, стяжка/бетон, кровля |
| D-13 | Для бухгалтерии: CSV/XLSX и PDF-инвойс |
| D-15 | Платежи на старте: один тестовый шлюз-заглушка с вводом карты в дизайне и зашитыми результатами для нескольких тестовых карт; реальные шлюзы позже через `PaymentProvider` |
| D-16 | SMS: Vonage; секреты и доступы (AWS, Figma, OAuth) подключаются позже, функциональность закладывается сразу |
| D-14 | Единицы измерения и упаковки, минимальная партия, цены по ступеням количества, резерв остатков |

## 6. Критерии успеха релиза

- Все сквозные сценарии (регистрация, поиск, проект, заказ у двух вендоров, оплата, доставка, возврат, выплата) проходят автотестами E2E.
- Покрытие тестами доменных пакетов не ниже 90%.
- Все экраны доступны на hy, ru, en без пропущенных ключей.
- Отчёт безопасности по главе из `05-cross-cutting-requirements.md` закрыт без критичных пунктов.
- `nx run progress:status` показывает 100% по плану релиза.
