# 01. Архитектура

Версии: «последняя стабильная на момент старта», фиксируются в lockfile и в ADR-0002. Автообновление запрещено без отдельной задачи.

## 1. Стек

| Слой | Решение |
|---|---|
| Язык | TypeScript (strict), Node.js LTS |
| Сервер | NestJS, REST + OpenAPI, WebSocket для чата |
| Веб | Angular (последняя), Tailwind, Angular Material только внутри `ui-web`, SSR с гидрацией для всех |
| Мобайл | NativeScript + Angular, отдельные view, пакет `ui-native` с тем же API компонентов, что у `ui-web` |
| Монорепо | Nx, генераторы Nx обязательны |
| Токены дизайна | Style Dictionary, один источник, выходы: CSS-переменные и тема Tailwind, тема Material, переменные NativeScript |
| Контракты | Zod-схемы в пакете contracts: типы, DTO, OpenAPI, типизированный клиент |
| Линтинг | Biome (формат и быстрые правила) + ESLint (остальное), генерация конфигов на лету из TOML |
| Тесты | Jest или Vitest (выбор в ADR), Testcontainers, Playwright, Storybook test-runner |

## 2. Хранилища

| Хранилище | Назначение |
|---|---|
| MongoDB | Основные данные: каталог, пользователи, вендоры, заказы, чаты, контент, настройки |
| PostgreSQL | Леджер двойной записи, кошельки, выплаты, платежи (строгие ограничения и транзакции) |
| Redis | Кэш, сессии, rate limiting, очереди (BullMQ) |
| OpenSearch | Лексический поиск с армянским анализатором, транслитерацией, синонимами; векторный поиск для ИИ-поиска |
| ClickHouse | События аналитики: заходы, источники, клики по рекламе, конверсии |
| S3 + CloudFront | Медиа, документы, экспорты |

Согласованность между хранилищами: паттерн **outbox**. Изменение в MongoDB и запись события в outbox делаются атомарно, воркер доставляет события в OpenSearch, ClickHouse и очереди. Все обработчики идемпотентны.

## 3. AWS (предложение, фиксируется в ADR-0003)

Регион по умолчанию: `eu-central-1`. Контейнеры на ECS Fargate. MongoDB: Atlas на AWS (DocumentDB не полностью совместим). RDS PostgreSQL, ElastiCache Redis, Amazon OpenSearch Service, ClickHouse Cloud на AWS, S3, CloudFront, SES (email), SMS через локального провайдера для Армении (интерфейс провайдера обязателен), Secrets Manager, WAF. IaC: Terraform или CDK (выбор в ADR). Окружения: dev (локально через Docker Compose), staging, prod. CI/CD: GitHub Actions.

## 4. Структура репозитория

```
apps/
  api/                 NestJS HTTP и WebSocket
  worker/              воркеры: очереди, outbox, медиа, импорт, выплаты, ИИ
  web-buyer/           Angular SSR
  web-vendor/          Angular
  web-admin/           Angular
  mobile-buyer/        NativeScript Angular
packages/<packageType>/<packageName>
  core/ts-utils        утилитарные типы TypeScript
  core/js-utils        частые функции (isString и т.д.)
  core/config          загрузчик конфигов (TOML + .env)
  core/bootstrap       класс бутстрапа сервера (сканер, валидация, Swagger, логирование, health)
  contracts/*          Zod-схемы и DTO по доменам
  design/tokens        Style Dictionary
  ui/ui-web, ui/ui-native, ui/ui-contracts
  tooling/lint, tooling/progress, tooling/seed, tooling/bootstrap-dev
  infra/*              клиенты БД, очередей, хранилищ, провайдеры (SMS, email, платежи, ИИ)
modules/<moduleName>/<platformName>
  пример: modules/catalog/api, modules/catalog/web, modules/catalog/native
```

Структура любого модуля или пакета:

```
src/
  @types/index.ts      все типы (внутренние и экспортируемые)
  lib/                 реализация
  index.ts             строго именованные экспорты публичного API
test/                  тесты (зеркалят lib/)
project.json
```

Допущение (ADR-0001): файлы называются в нижнем регистре (`index.ts`), чтобы не ломать сборку на Linux.
Границы между проектами обеспечиваются правилами Nx (`enforce-module-boundaries`) и тегами `scope:*`, `type:*`, `platform:*`. Модуль платформы `web` не импортирует `api` и наоборот, общее только через `contracts` и `core`.

## 5. Конфигурация

Для каждого модуля свой раздел в TOML (по окружениям) плюс `.env` для секретов. Загрузчик читает только свои ключи модуля, валидирует Zod-схемой на старте и падает с понятной ошибкой. Конфиг настроек, которые меняет админ в рантайме (комиссии, коэффициенты доставки, ступени лояльности, квоты ИИ), хранится в базе, а не в файле.

## 6. Дизайн-токены и UI

- Единый источник: `packages/design/tokens`. Цвета, типографика, отступы, радиусы, тени, брейкпоинты. Правка только там.
- Бренд вендора (цвета, логотип) переопределяет ограниченный набор токенов через CSS-переменные на странице вендора; обязательна проверка контраста (WCAG AA), при провале используется безопасный цвет.
- В `ui-web` обёрнуты стандартные компоненты Material и добавляются по необходимости. ESLint запрещает импорт `@angular/material` вне `ui-web`.
- Каждый компонент: Storybook-истории по состояниям, тесты доступности, i18n-готовность.

## 7. Общие механизмы

**Деньги.** Целые числа в минимальных единицах, всегда вместе с кодом валюты. Курс фиксируется в заказе в момент оформления. Источник курсов настраивается (интерфейс провайдера, по умолчанию курсы ЦБ Армении).

**Леджер.** Двойная запись в PostgreSQL: платёж покупателя, комиссия платформы, обязательство перед вендором, выплата, возврат, реклама, ИИ-кредиты. Любое денежное действие идемпотентно (ключ идемпотентности).

**Платёжные шлюзы.** Интерфейс `PaymentProvider` (создать платёж, статус, возврат, вебхук, сверка) и реестр провайдеров. Включение нескольких шлюзов, маршрутизация по правилам из админки. Добавление нового шлюза не должно менять доменный код.

**Права.** RBAC с матрицей «раздел × действие», область действия `platform` или `vendor:<id>`. Любой запрос к данным вендора проверяет принадлежность (защита от IDOR). Проверка прав в одном слое (guard), а не в каждом контроллере.

**Аутентификация.** Телефон (OTP, лимиты и защита от злоупотреблений), Google, Facebook. Токены: короткоживущий access и ротируемый refresh, для веба в httpOnly cookie. 2FA для админов и вендоров.

**Поиск.** Индексы по языкам, анализаторы hy, ru, en; транслитерация между письменностями; словарь синонимов из админки; допуск опечаток; векторные эмбеддинги мультиязычной модели. Ранжирование: релевантность, затем бизнес-сигналы; платные слоты отдельным блоком с пометкой «Реклама».

**Платное размещение.** Кампания вендора: тип `cpc` или `time`, бюджет с кошелька, позиции слотов, расписание. Клики дедуплицируются, боты фильтруются, подозрительные клики не списываются. Отчёты по кампаниям.

**Медиа.** Загрузка напрямую в S3 по presigned URL, воркер обрабатывает (изображения: ресайз, форматы, удаление EXIF; видео: транскодирование, превью), антивирусная проверка, CDN.

**ИИ.** Интерфейсы `TextProvider`, `ImageProvider`, `VideoProvider`, `EmbeddingProvider`, реестр провайдеров. Квоты и кредиты по вендору, лимиты на запрос, учёт стоимости, журнал вызовов, модерация результата, пометка сгенерированного контента, защита от prompt injection (контент вендоров считается недоверенным вводом).

**Импорт.** Интерфейс `ImportProvider`; на старте CSV и Excel: шаблоны, сопоставление колонок, предпросмотр, валидация построчно, отчёт об ошибках, откат, асинхронная обработка.

**Нотификации.** Каналы email, SMS, push (мобайл и web-push). Шаблоны локализованы и редактируются в админке. Покупатель включает и выключает типы событий по каналам. Критичные (коды входа, безопасность) отключить нельзя.

**Аналитика.** События с клиентов и сервера идут в очередь, затем батчами в ClickHouse. Вендору показываются заходы, источники, воронка, конверсия, продажи, рекламные метрики. Учёт согласия на cookie.

**Бутстрап для разработки.** `nx run bootstrap-dev:up`: проверяет и поднимает инфраструктуру через Docker Compose, создаёт индексы и схемы, выполняет миграции, загружает минимальный контент для запуска. Скрипт идемпотентный, прод не затрагивает.

**Seed.** `nx run seed:run`: страницы, переводы, настройки, категории и наборы свойств, около 100 разных осмысленных товаров с вариантами, изображениями и видео, вендоры, отзывы, заказы, жалобы, кампании. Данные детерминированы (seed-значение), повторный запуск не плодит дубли.

## 8. Нефункциональные цели

| Параметр | Цель |
|---|---|
| Нагрузка | ~50k MAU, ~100 RPS пик, горизонтальное масштабирование |
| Задержка | Чтение API p95 ≤ 300 мс, поиск p95 ≤ 400 мс |
| Доступность | 99,9% |
| Резервные копии | RPO ≤ 15 мин, RTO ≤ 1 ч, восстановление проверяется тестом |
| Веб | Core Web Vitals в зелёной зоне на мобильном профиле |
