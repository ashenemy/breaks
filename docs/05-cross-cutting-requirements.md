# 05. Сквозные и неявные требования

Эти требования действуют для каждого эпика, даже если в файле эпика они не повторены. Агент обязан их реализовать и проверить.

## 1. Локализация (i18n)

- Языки: hy, ru, en. Все строки интерфейса (кнопки, подписи, плейсхолдеры, ошибки валидации, письма, SMS, push, PDF, сообщения сервера) идут через ключи.
- Формат сообщений ICU с плюрализацией по правилам каждого языка. Числа, даты, валюты форматируются по локали.
- Цепочка fallback: запрошенный язык, затем ru, затем en. В продакшене отсутствие ключа логируется, в CI пропуск ключа ломает сборку.
- Переводы интерфейса редактируются в админке (с версиями и откатом). ИИ может предлагать перевод, человек подтверждает.
- Контент сущностей (название и описание товара, страницы вендора, категории, свойства) хранится по локалям. ИИ-помощник вендора предлагает переводы на недостающие языки.
- Слаги URL по локалям, теги `hreflang`, переключатель языка сохраняет страницу и параметры.
- Поддержка армянского письма: шрифты с нужным набором символов, корректная сортировка и регистр.
- Псевдолокализация в Storybook для поиска обрезаний и переполнений.

## 2. Доступность и интерфейс

- WCAG 2.2 AA: клавиатура, фокус, ARIA, контраст, масштабирование текста, уважение `prefers-reduced-motion`.
- Адаптив: mobile, tablet, desktop для всех порталов; вендорский портал полностью пригоден на телефоне.
- Для каждого экрана: состояния загрузки (скелетоны), пусто, ошибка с повтором, нет прав, офлайн в мобайле.
- Единая обработка ошибок: человекочитаемые сообщения на языке пользователя, код ошибки для поддержки.
- Формы: общая валидация из контрактов, сохранение черновиков для длинных форм, предупреждение о потере изменений.
- Темы: токены допускают светлую и тёмную тему; для витрины вендора допускается ограниченная кастомизация бренда.

## 3. SEO и маркетинг

- SSR с гидрацией, кэш на CDN, карта сайта по локалям, `robots.txt`, канонические ссылки.
- Разметка schema.org: Product, Offer, AggregateRating, BreadcrumbList, Organization.
- Открытые графы (Open Graph) для шаринга проектов и товаров.
- Режим «SSR только для ботов» включается переключателем в конфиге.

## 4. Данные и жизненный цикл

- Мягкое удаление для пользовательских данных и каталога, журнал аудита всех чувствительных действий (кто, что, когда, откуда, до и после).
- Версионирование товаров для споров (в заказе хранится снимок названия, цены, налогов, характеристик).
- Часовой пояс хранения UTC, отображение Asia/Yerevan и локальное время пользователя.
- Экспорт и удаление данных пользователя по запросу, согласие на cookie и обработку данных, юридические страницы редактируются в админке.
- Имперсонация («войти как») только для админов, с отдельным журналом и баннером.
- Импорт и экспорт везде асинхронные, с прогрессом, отчётом об ошибках и откатом.

## 5. Надёжность и наблюдаемость

- Структурные логи с correlation id, метрики, трассировка (OpenTelemetry), сбор ошибок.
- Health и readiness эндпоинты, graceful shutdown, ретраи с экспоненциальной паузой, dead-letter очереди.
- Идемпотентность всех денежных операций и вебхуков.
- Версионирование API, обратная совместимость в рамках мажорной версии.
- Feature flags для поэтапного включения функций.
- Rate limiting на публичных и чувствительных эндпоинтах.

## 6. Уведомления

- Каждое событие домена имеет таблицу: кому, по каким каналам, шаблон, можно ли отключить.
- Шаблоны локализованы, редактируются в админке, имеют предпросмотр.
- Критичные уведомления (коды, безопасность, платёжные) отключить нельзя.

## 7. Глава безопасности (модель угроз)

Целевой уровень: OWASP ASVS уровень 2. Модель угроз STRIDE по каждому эпику фиксируется в файле эпика (раздел «Угрозы»).

| Область | Требования |
|---|---|
| Доступ | RBAC на уровне guard; обязательная проверка принадлежности ресурса вендору (IDOR); 2FA для админов и вендоров; сессии с ротацией и отзывом |
| Вход по телефону | Лимиты на отправку OTP и попытки ввода, защита от SMS-pumping (лимиты по номеру, IP, устройству, региону), блокировка массовых запросов |
| Платежи | Подпись и проверка вебхуков, идемпотентность, сверка с банком, запрет изменения суммы на клиенте, защита от double-spend |
| Реклама | Антифрод кликов: дедупликация, эвристики ботов, лимиты на IP и устройство, возврат подозрительных списаний |
| Загрузки | Проверка типа по содержимому, лимиты размера, антивирус, удаление EXIF, раздача с отдельного домена |
| Rich-text и вывод | Санитизация HTML, экранирование, строгая CSP |
| Экспорты | Защита от CSV-инъекций (экранирование формул) |
| ИИ | Prompt injection: контент вендоров и пользователей считается недоверенным; изоляция системных инструкций; ограничение инструментов; фильтрация вывода; лимиты стоимости и частоты |
| Сеть | SSRF-защита для импорта по URL и ИИ-запросов, allow-list исходящих доменов |
| Данные | Шифрование в покое и в транзите, шифрование чувствительных полей, секреты в Secrets Manager, ротация ключей |
| Цепочка поставок | Lockfile, аудит зависимостей в CI, запрет неподписанных образов, SBOM |
| Инфраструктура | WAF, DDoS-защита, минимальные права IAM, сетевая сегментация, резервные копии с проверкой восстановления |
| Журналы | Неизменяемый аудит, алерты на подозрительную активность |

## 8. Чек-лист агента на каждый эпик

1. Права и роли описаны и проверены тестами (включая отрицательные).
2. Все строки в i18n, переводы hy, ru, en.
3. Состояния интерфейса реализованы.
4. Аудит и события домена записываются.
5. Уведомления и шаблоны определены.
6. Угрозы описаны, меры реализованы и протестированы.
7. Метрики и логи добавлены.
8. Seed и миграции обновлены.
9. Документация модуля обновлена.
