# START: запуск автопилота

## 1. Подготовка (один раз)

1. Создать пустой репозиторий (GitHub), скопировать в корень этот пакет (`AGENTS.md`, `.github/`, `docs/`, `README.md`).
2. Включить GitHub Copilot в режиме агента. Основная модель: самая современная Claude; для шаблонного кода допустима более лёгкая (доступность моделей проверить в настройках Copilot).
3. Установить на машину агента: Node.js LTS, pnpm, Docker, git. Больше ничего не требуется для M0 и M1.
4. Включить защиту ветки `main` (только через pull request, обязательные проверки CI).
5. Секреты, аккаунты и платные сервисы пока не нужны: везде заложены заглушки (SMS, платежи, ИИ, почта, push, расстояния). Список того, что понадобится позже, в разделе 4.

## 2. Первый промпт для Copilot

> Ты автономный инженер проекта. Прочитай `AGENTS.md`, затем `docs/02-code-conventions.md`, `docs/03-autopilot-protocol.md` и `docs/04-roadmap.md`. Начни с эпика E00.01 (`docs/epics/E00.01-monorepo-nx.md`): выполняй задачи строго по цепочке зависимостей, каждую в своей ветке `autopilot/<task-id>`. После E00.01 переходи к E00.02, E00.03, E00.10 (инструмент прогресса) и дальше по плану. Работай по циклу из протокола: тест, реализация, линтинг, коммит по формату, `progress checkpoint`. Не останавливайся на неясностях: выбирай вариант по приоритету документов, записывай допущение в `docs/decisions/assumptions.md` и продолжай. Останавливайся только на задачах типа `gate` и при отсутствии внешнего секрета. До готовности инструмента прогресса веди файл `docs/progress/MANUAL.md` (id задачи, статус, коммит).

## 3. Каждая следующая сессия

> Выполни `nx run progress:resume` и продолжи с указанного места. Если инструмент ещё не готов, прочитай `docs/progress/MANUAL.md` и `git log -10`, найди последнюю завершённую задачу и продолжи со следующей готовой.

После сбоя компьютера делать то же самое: сначала `git status` и `git log`, затем `resume`.

Gate-задачи агент не закрывает. Человек закрывает их командой `progress approve <id>`.

## 6. Что проверено автоматически

- Все id задач уникальны, все зависимости существуют, циклов нет.
- Каждая задача, кроме gate, имеет команду приёмки; вес из набора 1, 2, 3, 5, 8; scope начинается с `apps`, `packages`, `modules` или `root`.
- Эпики в `docs/04-roadmap.md` и файлы в `docs/epics/` совпадают по составу.
- Первые UI-задачи каждого портала зависят от утверждения макетов (gate).
