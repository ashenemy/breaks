# E00.01. Монорепо Nx

Этап: M0. Зависимости: нет.

## 1. Цель
Создать каркас репозитория, в котором структура, границы и шаблоны проектов обеспечиваются инструментами, а не памятью агента.

## 2. Требования
- Менеджер пакетов: pnpm (фиксируется в ADR-0002), версия Node через `.nvmrc` и `engines`.
- Корневые каталоги: `apps/`, `packages/<packageType>/<packageName>`, `modules/<moduleName>/<platformName>`.
- Теги: `scope:<домен|shared>`, `type:<app|core|contracts|ui|tooling|infra|module>`, `platform:<api|web|native|shared>`.
- Правила границ: `platform:web` не зависит от `platform:api` и наоборот; `platform:native` не зависит от `platform:web`; всё общее живёт в `type:core` и `type:contracts`; `type:tooling` не импортируется из приложений.
- Генераторы **оборачивают** официальные плагины Nx (`@nx/js`, `@nx/nest`, `@nx/angular`, `@nativescript/nx` и т.д.), не заменяют их. Каждый генератор создаёт: `src/@types/index.ts`, `src/lib/`, `src/index.ts`, `test/`, `project.json` с целями `lint`, `test`, `build`, `README.md` модуля, теги, настройки тестов и покрытия.
- Генератор `module` создаёт набор проектов `modules/<name>/{api,web,native}` по выбору платформ и общий контрактный пакет при необходимости.
- Проект, созданный не генератором, не проходит CI-проверку «проект создан генератором» (по маркеру в `project.json`).

## 3. Сценарии
- Агент выполняет `nx g @market/tooling:lib --name=ts-utils --type=core`, получает готовый проект, который сразу проходит lint и test.
- Попытка импортировать `apps/api` из `modules/catalog/web` блокируется линтером.

## Задачи
```yaml
tasks:
  - id: E00.01.01
    title: "Инициализировать рабочее пространство Nx (TypeScript strict, менеджер пакетов зафиксирован)"
    scope: root/workspace
    weight: 2
    deps: []
    acceptance:
      - cmd: nx graph --file=tmp/graph.json
      - cmd: nx run-many -t build --all --skip-nx-cache
  - id: E00.01.02
    title: "Теги проектов и правила границ (scope, type, platform) через enforce-module-boundaries"
    scope: root/workspace
    weight: 3
    deps: [E00.01.01]
    acceptance:
      - cmd: pnpm test:boundaries
  - id: E00.01.03
    title: "Кастомные генераторы-обёртки над официальными плагинами Nx (lib, nest-app, angular-app, nativescript-app, module)"
    scope: packages/tooling/generators
    weight: 5
    deps: [E00.01.02]
    acceptance:
      - cmd: nx test tooling-generators
  - id: E00.01.04
    title: "Скрипты affected для CI, кэш Nx, наставление в README корня"
    scope: root/workspace
    weight: 2
    deps: [E00.01.03]
    acceptance:
      - cmd: nx affected -t lint test build --base=HEAD~1
```

## 9. Критерии приёмки
- Генераторы создают валидные проекты всех типов, проверено тестами генераторов.
- Нарушение границ ловится линтером (негативный тест).
- Пустое пространство собирается и проходит `nx run-many -t lint test build`.

## 10. Вне объёма
Настройка CI (E00.13), правила стиля кода (E00.02).
