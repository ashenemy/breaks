# E00.02. Пакет `tooling/lint`: конфиги на лету, раннер, хуки, коммиты

Этап: M0. Зависимости: E00.01.

## Цель
Единый источник правил в TOML, генерация конфигов Biome и ESLint на лету, свой раннер, хуки и проверка формата коммитов. Агент не может нарушить стиль.

## Требования
1. Единственный ручной источник: `packages/tooling/lint/rules.toml` с разделами `[format]`, `[naming]`, `[members]`, `[imports]`, `[types]`, `[angular]`, `[i18n]`, `[boundaries]`, `[commits]`, плюс переопределения по платформам. Схема валидируется Zod.
2. Генерация: раннер строит `biome.json` и `eslint.config.mjs` в корне, оба в `.gitignore`. Хеш TOML и версий инструментов хранится в `.cache/lint/hash`. Файлы пересоздаются при `postinstall` и перед каждым запуском при изменении хеша.
3. Соответствие правил (источник: TOML):
   - Отступ 4 пробела, LF, ширина строки из TOML (по умолчанию 120): Biome.
   - `consistent-type-definitions: type`, `consistent-type-imports` и `consistent-type-exports` с `import type` и `export type`.
   - `no-explicit-any`: ошибка.
   - Именование (`@typescript-eslint/naming-convention`): переменные `export const` и поля `public static readonly` в `UPPER_CASE`; private члены в `camelCase` с обязательным `__` (`leadingUnderscore: requireDouble`); protected в `camelCase` с обязательным `_` (`require`); public в `camelCase` без подчёркивания (`forbid`); типы и классы `PascalCase`. Экспортируемые функции объявляются через `export function`, а не `export const`.
   - Порядок членов класса: `@typescript-eslint/member-ordering` с последовательностью из `02-code-conventions.md`.
   - Явные типы в классах: `explicit-member-accessibility`, `explicit-function-return-type` и `typedef` для полей и параметров методов, конструктор исключён.
   - Только именованные экспорты: запрет `export default` и `export *` (кроме конфигов инструментов, перечисленных в TOML).
   - Сортировка импортов и экспортов: Biome (или `simple-import-sort`, если Biome не покрывает группы; решение в ADR-0009).
   - Запрет импорта `@angular/material` вне `ui-web`; запрет нативных `<input>`, `<button>` и т.д. в шаблонах вне `ui-web`.
   - Запрет захардкоженного текста в шаблонах Angular и в `ui-native` (правило i18n).
   - Правила Angular из `angular-eslint`, границы Nx.
   - Пересекающиеся правила Biome и ESLint включены ровно в одном инструменте (список в TOML).
4. Раннер `nx run lint:run`: режимы `--staged`, `--affected`, `--fix`, `--ci`, `--format-only`; кэш; единый JSON и текстовый отчёт; ненулевой код возврата при ошибках.
5. Хуки: каталог `.githooks` в репозитории, `core.hooksPath` устанавливается при `postinstall`.
   - `pre-commit`: раннер `--staged --fix`, затем добавление исправленных файлов в индекс.
   - `commit-msg`: проверка регулярного выражения `^(✨ feat|🐛 fix|♻️ refactor|🧪 test|📝 docs|🔧 chore|⚡ perf|🎨 style|🔒 security|🏗️ build|🗃️ db): (apps|packages|modules|root)/[a-z0-9/_-]+: .{1,72}$` и соответствия иконки типу. Затем определяет проект Nx для каждого застейдженного файла по графу проектов. Файлы должны принадлежать одному проекту. Корневые файлы допустимы только со scope `root/...`. Исключения нет.
   - `pre-push`: типизация и тесты `affected`.
6. Обход хуков запрещён. CI повторяет все проверки, включая проверку формата и состава коммитов в PR.

## Критерии приёмки
- Для каждого правила из пункта 3 есть фикстура с нарушением, которую раннер отклоняет с ожидаемым сообщением.
- Правка `rules.toml` без ручного изменения других файлов меняет поведение линтинга.
- Коммит с файлами из двух проектов отклоняется; коммит с неверным форматом или парой иконка-тип отклоняется.
