# E00.03. Модуль конфигурации `core/config`

Этап: M0. Зависимости: E00.01.

## Цель
Единый загрузчик конфигов: TOML для несекретных настроек, `.env` для секретов, типизация и валидация на старте.

## Требования
1. Файлы: `config/default.toml`, `config/<env>.toml` (`dev`, `test`, `staging`, `prod`), `config/local.toml` (в `.gitignore`). Слияние по порядку: default, окружение, local, затем переменные окружения.
2. Каждый модуль имеет раздел `[modules.<name>]` и Zod-схему. Модуль читает только свой раздел и свои секреты.
3. Секреты: только из переменных окружения или `.env` (локально) и AWS Secrets Manager (в проде, через инъекцию в окружение контейнера). Секрет в TOML вызывает ошибку валидации (список запрещённых ключей: `secret`, `password`, `token`, `key`).
4. Переопределение через окружение: `APP__MODULES__<NAME>__<KEY>`.
5. API: `defineModuleConfig(name, schema)` возвращает типизированный токен; для Nest `ConfigModule.forModule(token)`; для не-Nest кода `loadModuleConfig(token)`.
6. Старт падает с понятным сообщением, если конфиг не прошёл валидацию (какой модуль, какой ключ, ожидаемый тип).
7. Конфиг неизменяем в рантайме. Настройки, которые меняет админ (комиссии, коэффициенты, ступени лояльности, квоты ИИ), хранятся в базе (эпик E01.05 и профильные эпики).
8. Значения секретов не попадают в логи и в ответы API (маскирование).

## Критерии приёмки
- Тесты слоёв: порядок слияния, переопределение окружением, отсутствие обязательного ключа, неверный тип, секрет в TOML.
- Модуль не может прочитать чужой раздел (тест).
