# E00.04. Bootstrap

Этап: M0. Зависимости: E00.03.

## 1. Цель
Одной командой получить рабочее dev-окружение и одним классом настроить любой сервер.

## 2. Требования
- `ServerBootstrap.create(options)` настраивает: загрузку конфига, структурные логи с correlation id, глобальную валидацию по Zod-схемам, генерацию OpenAPI и Swagger UI (только не в проде), helmet, CORS по конфигу, rate limiting на Redis, `/health` и `/ready`, перехват сигналов и graceful shutdown, версионирование API (`/v1`), обработчик ошибок с единым форматом.
- Сканер находит Nest-модули по соглашению об имени и регистрирует их без ручного перечисления в `AppModule`.
- `nx run tooling-bootstrap-dev:up` проверяет наличие Docker, поднимает сервисы, ждёт готовности, создаёт индексы OpenSearch и коллекции MongoDB, выполняет миграции PostgreSQL, загружает минимальный контент (базовые роли, языки, валюты, настройки по умолчанию). Повторный запуск не ломает состояние.
- MongoDB запускается как replica set (нужны транзакции).
- `reset` очищает данные только dev-окружения и защищён от запуска при `env != dev`.
- Слой данных (`packages/infra/db`): подключение к MongoDB с поддержкой транзакций и базовый класс репозитория (мягкое удаление, версия документа, аудит полей создания и изменения), таблица `outbox` и воркер доставки событий, клиент PostgreSQL и раннер миграций. Слой очередей (`packages/infra/queue`): BullMQ, ретраи с экспоненциальной паузой, dead-letter, идемпотентные обработчики.
- Скрипт не устанавливает и не меняет ничего вне Docker и не затрагивает прод.

## 8. Угрозы и меры
Случайный запуск `reset` на не-dev: проверка окружения и отказ. Порты сервисов dev слушают только localhost.

## 9. Критерии приёмки
- Пустой Nest-проект стартует через `ServerBootstrap` с health, OpenAPI, логами и graceful shutdown (интеграционный тест).
- `up` дважды подряд даёт одинаковое состояние, `down` и `up` восстанавливают окружение.
- Добавление нового Nest-модуля по конвенции подхватывается сканером без правок `AppModule`.
