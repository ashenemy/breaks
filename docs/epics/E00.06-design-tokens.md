# E00.06. Токены дизайна `design/tokens` (Style Dictionary)

Этап: M0. Зависимости: E00.01.

## Цель
Один источник правды для цветов, типографики, отступов и прочего, с выходами для Tailwind, Angular Material и NativeScript.

## Требования
1. Формат источника: токены в JSON по спецификации DTCG (`$value`, `$type`), разбиты по файлам: `color`, `typography`, `spacing`, `radius`, `shadow`, `breakpoint`, `motion`, `z-index`.
2. Темы: `light` и `dark` (семантические токены ссылаются на базовые палитры). Брендовый слой вендора: ограниченный набор `color.brand.*` (основной, акцентный, на-основном) переопределяется в рантайме через CSS-переменные.
3. Выходы (генерируются сборкой, в git не коммитятся, кроме снимков в тестах):
   - CSS-переменные (`variables.css`) для веба.
   - Тема Tailwind (конфигурация или CSS-блок темы в зависимости от версии Tailwind, зафиксированной в ADR-0002).
   - Тема Angular Material (Material 3): палитры и плотность из токенов.
   - Переменные и SCSS для NativeScript (с учётом ограничений CSS в NativeScript; список поддерживаемых возможностей проверяется в E00.12).
   - TypeScript-константы токенов для логики (например, расчёт контраста).
4. Проверка контраста: утилита `ensureContrast(foreground, background, level = 'AA')`. Брендовые цвета вендора проходят через неё; при провале подставляется безопасный цвет и выставляется флаг для вендорского UI.
5. Синхронизация с Figma: переменные Figma и токены сопоставляются по именам (маппинг в `tokens.config`); в M0.5 используется для дизайна. Нужна команда `tokens:export-figma` и `tokens:import-figma` (формат уточняется в ADR-0010).
6. Правка токена в одном месте меняет все выходы после `nx run design-tokens:build`.

## Критерии приёмки
- Изменение одного цвета в источнике отражается в CSS, теме Tailwind, теме Material и выходе NativeScript (снимочные тесты).
- Брендовый цвет с недостаточным контрастом заменяется безопасным (тест).
