# E00.07. Контракты `contracts`: Zod-схемы, DTO, OpenAPI, клиент

Этап: M0. Зависимости: E00.01, E00.05.

## Цель
Единый источник правды по форме данных для сервера, веба и мобайла. Из схем выводятся типы, DTO, документация OpenAPI и типизированный клиент.

## Требования
1. Структура: `packages/contracts/<domain>`; общий пакет `packages/contracts/common`.
2. В `common`:
   - `EntitySchema`: `id` (строка ObjectId для MongoDB), `createdAt`, `updatedAt`, `deletedAt` (опционально), `version` (оптимистичная блокировка).
   - `LocalizedTextSchema`: `{ hy?, ru?, en? }` плюс правила полноты (обязателен хотя бы один язык, уровни обязательности настраиваются по сущности).
   - `MoneySchema` (согласовано с `core/money`), `CurrencyCodeSchema`, `PaginationSchema` (курсорная и страничная), `SortSchema`, `FilterSchema`.
   - `ApiErrorSchema`: `code` (стабильный машинный код), `messageKey` (i18n-ключ), `details`, `correlationId`.
   - `PhoneSchema` (E.164, префикс +374 по умолчанию), `EmailSchema`, `SlugSchema`.
3. Помощники для производных схем: `deriveCreate(schema)`, `deriveUpdate(schema)`, `deriveResponse(schema)`: из базовой схемы убираются служебные поля, делаются частичными и т.д. Типы выводятся через `z.infer`.
4. Серверная интеграция: pipe валидации в Nest на этих схемах, DTO для Swagger генерируются из схем.
5. OpenAPI: генерация спецификации из схем и маршрутов в артефакт `openapi.json`, проверка совместимости с предыдущей версией (breaking changes ломают CI).
6. Клиент: генерация типизированного клиента (`fetch`-обёртка с перехватчиками для Angular и NativeScript) в пакет `contracts/client`. Ошибки приходят как типизированный `ApiError`.
7. Ни одна схема не содержит декораторов Nest или class-validator.

## Критерии приёмки
- Изменение схемы меняет типы сервера и клиента без ручных правок.
- Нарушающее совместимость изменение схемы валит CI до явного повышения версии API.
