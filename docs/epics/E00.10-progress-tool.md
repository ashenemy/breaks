# E00.10. Инструмент прогресса `tooling/progress`

Этап: M0. Зависимости: E00.01. Реализовывать как можно раньше (сразу после E00.01), потому что остальная работа опирается на него.
Спецификация поведения: `docs/03-autopilot-protocol.md`, раздел 4.

## Цель
Показывать общий и текущий прогресс, не давать агенту самому объявлять задачу выполненной и позволять продолжить с правильного места после сбоя.

## Требования
1. Сборка плана: парсер находит в `docs/epics/*.md` блоки ```` ```yaml ```` с ключом `tasks:` и строит `docs/progress/plan.yaml` (валидация схемы, уникальность id, проверка зависимостей на циклы и на несуществующие id).
2. Состояние: `docs/progress/state.yaml` хранит статус, даты, SHA коммита завершения, заметки. Коммитится отдельным коммитом `🔧 chore: root/progress: ...` при завершении задачи.
3. Локальный контекст: `.progress/checkpoint.json` (атомарная запись: временный файл, fsync, rename) и `.progress/journal.ndjson`.
4. Команды из протокола: `status`, `resume`, `checkpoint`, `start`, `verify`, `block`, `split`, `report`. Кроме них: `next` (какую задачу брать), `graph` (зависимости).
5. `verify <id>`: выполняет все `acceptance.cmd`, проверяет, что `scope` совпадает с затронутыми коммитами задачи, что нет незакоммиченных изменений в `scope`, что линтинг и типизация проекта проходят, что i18n-проверка (если есть UI) зелёная. Только тогда статус `done`.
6. `status`: взвешенные полосы прогресса (общий, по этапам, по эпикам), текущая задача с оценкой по подшагам (помечается `~`), число `blocked`, ближайшие готовые к старту задачи.
7. `resume`: алгоритм из раздела 4.5 протокола; выводит готовый промпт для чата Copilot.
8. Требования к коммитам задачи: в теле `Task: <id>` и `Substep: <n>`. `resume` восстанавливает прогресс по этим меткам, если checkpoint потерян.
9. Симуляция сбоя: тестовый стенд убивает процесс в разные моменты записи, повреждает checkpoint и подменяет HEAD; инструмент должен восстановиться или честно сообщить, что требуется проверка.
10. Отчёт: `REPORT.md` и необязательная статическая HTML-страница с теми же данными.

## Задачи
```yaml
tasks:
  - id: E00.10.01
    title: "Парсер epics в plan.yaml, валидация графа зависимостей"
    scope: packages/tooling/progress
    weight: 3
    deps: [E00.01.03]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=plan
  - id: E00.10.02
    title: "state.yaml и checkpoint.json: схемы, атомарная запись, журнал"
    scope: packages/tooling/progress
    weight: 3
    deps: [E00.10.01]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=storage
  - id: E00.10.03
    title: "Команды start, checkpoint, block, split, next, graph"
    scope: packages/tooling/progress
    weight: 3
    deps: [E00.10.02]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=commands
  - id: E00.10.04
    title: "Команда verify (acceptance, scope, lint, типизация, i18n)"
    scope: packages/tooling/progress
    weight: 5
    deps: [E00.10.03]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=verify
  - id: E00.10.05
    title: "Команда status и расчёт прогресса, отрисовка в терминале"
    scope: packages/tooling/progress
    weight: 3
    deps: [E00.10.03]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=status
  - id: E00.10.06
    title: "Команда resume, восстановление по git, готовый промпт"
    scope: packages/tooling/progress
    weight: 5
    deps: [E00.10.04]
    acceptance:
      - cmd: nx test tooling-progress --testPathPattern=resume
  - id: E00.10.07
    title: "Стенд симуляции сбоев и report"
    scope: packages/tooling/progress
    weight: 3
    deps: [E00.10.06, E00.10.05]
    acceptance:
      - cmd: nx e2e tooling-progress-e2e
```

## Критерии приёмки
- После принудительного завершения процесса в любой момент `resume` возвращает корректную текущую задачу и следующее действие.
- Агент не может перевести задачу в `done`, минуя `verify`.
- `status` показывает общий и текущий прогресс для плана из всех эпиков.
