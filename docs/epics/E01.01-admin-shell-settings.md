# E01.01. Каркас админ-портала и фреймворк настроек платформы

Этап: M1. Зависимости: E00.09, E00.11, E00.08, E00.04.

## 1. Цель
Дать администраторам рабочее приложение и единый механизм типизированных настроек, на котором позже строятся комиссии, коэффициенты доставки, ступени лояльности, квоты ИИ и т.д.

## 2. Требования
- `apps/web-admin` (Angular SSR не нужен, SPA), создаётся генератором. Только компоненты `ui-web`.
- Навигация формируется из реестра разделов; пункт виден, только если у пользователя есть право `view` на раздел. Маршруты защищены тем же правилом.
- Вход персонала: логин и пароль, затем 2FA (TOTP). Экраны: вход, ввод кода, восстановление, смена пароля, 403, 404, ошибка.
- Фреймворк настроек (`modules/settings`): каждый модуль регистрирует настройки (`namespace`, `key`, Zod-схема, значение по умолчанию, описание, права на изменение). Хранение в MongoDB, версии, кто и когда менял, откат к версии, кэш в Redis с инвалидацией событием.
- Универсальная форма настроек строится автоматически по Zod-схеме (поля, группы, валидация, подсказки на трёх языках).
- Управление персоналом платформы: список, приглашение, блокировка, роли (админ, модератор, саппорт, арбитр, бухгалтер, логист), редактор матрицы «раздел × действие».
- Дашборд с реестром виджетов (на этом этапе пустое состояние, виджеты добавляют следующие эпики).

## 3. Сценарии
Админ меняет значение настройки, видит предпросмотр различий, сохраняет; значение применяется без перезапуска; в аудите запись «до и после». Откат возвращает предыдущую версию.

## 5. Права, аудит, события
Разделы: `settings`, `staff`, `roles`. Действия: `view`, `edit`. Все изменения в аудит-лог. Событие `settings.changed`.

## 7. Ключи i18n
`admin.shell.*`, `admin.settings.*`, `admin.staff.*`, `admin.auth.*`.

## 8. Угрозы и меры
Эскалация прав: нельзя выдать роль выше собственной и нельзя отозвать последнего админа. Подмена настроек: схема проверяется на сервере, изменение критичных настроек требует повторного подтверждения 2FA.

## 9. Критерии приёмки
- Пользователь без права `view` не видит пункт меню и получает 403 по прямой ссылке (тесты).
- Изменение настройки применяется во всех экземплярах API без перезапуска (интеграционный тест с двумя процессами).
- Откат версии восстанавливает значение и пишет аудит.
- Нельзя убрать последнего админа и нельзя выдать роль выше своей.

## 10. Вне объёма
Конкретные настройки комиссий, доставки, лояльности (в своих эпиках).
