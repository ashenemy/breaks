# E01.09. Модерация: вендоры, товары, пользователи, отзывы, оценки

Этап: M1. Зависимости: E01.01, E01.03, E00.09.

## 1. Цель
Единый каркас модерации с очередями, решениями, причинами, SLA и аудитом. Конкретные источники (онбординг вендоров, отзывы) подключаются в своих эпиках через регистрацию типа дела.

## 2. Сущности
- **ModerationCase**: `type` (`product`, `vendor`, `review`, `user`, `media`, `chat_report`), `targetRef`, `status` (`new`, `in_review`, `approved`, `rejected`, `needs_changes`, `escalated`), `priority`, `assigneeId`, `reasonCodes[]`, `comment`, `slaDueAt`, `source` (`auto`, `user_report`, `submission`), `history[]`.
- **ReasonCode**: код, локализуемый текст для владельца объекта, признак «можно исправить».
- **ModerationPolicy**: набор автопроверок для типа дела.

## 3. Требования
- Реестр типов дел: модуль регистрирует тип, обработчики применения решения (approve, reject, needs_changes), способ показа объекта и права.
- Очереди с фильтрами (тип, статус, исполнитель, SLA, приоритет), взятие в работу с блокировкой от одновременной обработки, передача, эскалация.
- Решения с обязательной причиной при отказе; решение применяется к объекту (например товар переходит из `pending_moderation` в `published` или `rejected`), владельцу уходит уведомление с локализованной причиной.
- Автопроверки до попадания в очередь: запрещённые слова и ссылки (списки из настроек), дубли товаров (по хешу и похожести названия), подозрительные цены, контакты в описании. Хук для ИИ-премодерации (подключается в E02.05). Автоодобрение для доверенных вендоров по настройке.
- SLA: таймер, просрочка помечается и эскалируется.
- Блокировка и разблокировка пользователей и вендоров с причиной, срок блокировки, апелляция.
- Массовые действия над делами (одобрить, отклонить с причиной).
- Все действия в аудит; метрики: размер очереди, среднее время решения, доля отклонений по причинам.

## 5. Права, аудит, события
Раздел `moderation` с действиями по типам (`products.review`, `vendors.review`, `reviews.review`, `users.block`). События `moderation.decided`, `user.blocked`.

## 6. Уведомления
Владельцу объекта: отправлено на проверку, одобрено, отклонено с причиной, нужны правки, блокировка (шаблоны из E01.05).

## 7. Ключи i18n
`admin.moderation.*`, `moderation.reason.*`.

## 8. Угрозы и меры
Обход модерации прямым изменением статуса (смена статуса только через сервис решения), злоупотребление блокировкой (двойное подтверждение и аудит), утечка данных жалобщика (скрывается от владельца).

## 9. Критерии приёмки
- Товар с запрещённым словом попадает в очередь с пометкой автопроверки; одобрение публикует товар, отказ возвращает вендору причину на его языке.
- Один дело не может обрабатываться двумя модераторами одновременно.
- Просроченные по SLA дела эскалируются.
- Заблокированный пользователь теряет доступ сразу (сессии отзываются).
- Любое действие модератора есть в аудите.

## 10. Вне объёма
Онбординг вендоров (E02.01), отзывы покупателей (E04.04), ИИ-премодерация (E02.05).
