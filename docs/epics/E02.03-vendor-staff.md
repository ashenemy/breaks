# E02.03. Сотрудники вендора и матрица прав

Этап: M2. Зависимости: E02.01, E00.09.05, E00.09.06.

## 1. Цель
Владелец добавляет сотрудников и ограничивает доступ по разделам и действиям (например маркетолог видит только статистику).

## 2. Сущности
- **VendorMember**: `vendorId`, `userId`, `roleId`, `status` (`invited`, `active`, `disabled`), `invitedBy`, `lastActiveAt`.
- **Role** (область `vendor:<id>`): матрица «раздел × действие». Разделы: `products`, `orders`, `chat`, `complaints`, `reviews`, `analytics`, `finance`, `storefront`, `import`, `staff`, `advertising`, `ai`, `company`. Действия: `view`, `create`, `edit`, `delete`, `publish`, `export` (по применимости).
- Готовые роли: владелец, менеджер, менеджер заказов, склад, маркетолог (аналитика, реклама, витрина), бухгалтер (финансы, выгрузки). Вендор может создавать свои роли на базе готовых.

## 3. Требования
- Приглашение по телефону или email со ссылкой с коротким сроком; принятие с созданием пароля и обязательной 2FA.
- Владелец неудаляем и не может лишить себя права управления сотрудниками; передача владения отдельным действием с подтверждением 2FA.
- Нельзя выдать права, которых нет у приглашающего.
- Изменение роли действует немедленно (отзыв кэшей и сессионных прав).
- Сотрудник может состоять в нескольких вендорах, переключатель вендора в интерфейсе.
- Журнал действий по сотрудникам, список активных сессий, принудительный выход.
- Интерфейс скрывает недоступные разделы, а сервер проверяет права независимо (guard из E00.09.06).
- Лимит числа сотрудников по настройке платформы.

## 5. Права, аудит, события
Раздел `staff` (view, create, edit, delete). События `member.invited`, `member.role_changed`, `member.disabled`. Всё в аудит.

## 6. Уведомления
Приглашение, смена роли, отключение.

## 7. Ключи i18n
`vendor.staff.*`, `vendor.roles.*`, `vendor.sections.*`.

## 8. Угрозы и меры
Эскалация привилегий, захват приглашения (одноразовый токен, привязка к контакту), забытые доступы (отчёт о неактивных сотрудниках, автоотключение по настройке).

## 9. Критерии приёмки
- Маркетолог по прямым ссылкам и API получает 403 везде, кроме аналитики, рекламы и витрины.
- Сотрудник не может выдать роль выше своей, владельца нельзя удалить.
- Смена роли действует без повторного входа.

## 10. Вне объёма
Конкретные действия в разделах (в их эпиках).
