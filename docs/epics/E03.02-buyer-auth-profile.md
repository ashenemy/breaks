# E03.02. Регистрация, вход и профиль покупателя

Этап: M3. Зависимости: E00.09, E00.04.05, E03.01.01.

## 1. Цель
Вход по номеру телефона (OTP), через Google и Facebook; профиль, адреса, приватность. Защита от злоупотреблений SMS.

## 2. Требования
- **Интерфейсы провайдеров**: `SmsProvider` (реализации: Vonage, заглушка с журналом для dev), `OAuthProvider` (Google, Facebook, моки для dev), `ChallengeProvider` (проверка на бота, заглушка). Ключи подключаются позже через секреты.
- **OTP**: одноразовый код, хранится только хеш, срок действия, ограничение попыток, повторная отправка с нарастающей паузой, лимиты по номеру, IP, устройству, стране и общему объёму в час, детектор «SMS pumping» (массовые запросы на номера одного диапазона и необычные регионы), блокировка при превышении, метрики и алерты.
- **Вход и регистрация**: единый поток «введите номер, получите код». Социальный вход создаёт или находит аккаунт. Политика привязки: один человек может связать телефон, Google, Facebook; совпадение по подтверждённому номеру объединяет аккаунты, совпадение только по email из соцсети без подтверждения не объединяет автоматически.
- **Сессии и токены** из E00.09.03: список устройств, выход со всех устройств, отзыв.
- **Профиль**: имя, язык, предпочтительная валюта, подтверждённый телефон, смена телефона с подтверждением нового и старого номера, при необходимости email (необязательно, с подтверждением).
- **Адресная книга** (структура для Армении): область (марз), населённый пункт или район Еревана, улица, дом, квартира, этаж, подъезд, домофон, индекс, комментарий для курьера, точка на карте (широта, долгота), получатель и телефон получателя; адрес по умолчанию; валидация обязательных полей; интерфейс геокодера `GeocodeProvider` (заглушка, затем реальный).
- **Слияние гостя и аккаунта**: после входа корзина, проекты и согласия гостя переносятся по событию `guest.merged`.
- **Приватность**: согласия (учёт версий), экспорт данных пользователя (асинхронно, файл по подписанной ссылке), удаление аккаунта (анонимизация персональных данных, сохранение обезличенных записей о заказах по требованиям учёта и спорам).
- **Блокировка**: заблокированный пользователь получает понятное сообщение и не может войти (E01.09).
- **Интерфейс**: модальное окно и страница входа (номер, код, соцкнопки), состояния ошибок и лимитов, страницы аккаунта: профиль, адреса, устройства, приватность.

## 5. Права, аудит, события
События `buyer.registered`, `buyer.logged_in`, `buyer.phone_changed`, `guest.merged`, `buyer.deleted`. Аудит смены телефона, привязок, удаления.

## 6. Уведомления
Код входа (SMS, критичное), новая привязка способа входа, смена телефона, экспорт готов.

## 7. Ключи i18n
`buyer.auth.*`, `buyer.profile.*`, `buyer.address.*`, `buyer.privacy.*`.

## 8. Угрозы и меры
SMS pumping и перебор кодов (лимиты, challenge, алерты), захват аккаунта через социальную привязку (правила объединения), SIM-swap (уведомление о смене телефона, повторная проверка для критичных действий), перечисление номеров (одинаковые ответы для существующих и новых), CSRF в OAuth (state и PKCE).

## 9. Критерии приёмки
- Вход по номеру через заглушку и Vonage-адаптер (на контрактных тестах); неверные коды блокируются после лимита.
- Серия запросов на номера одного диапазона срабатывает как pumping и блокируется.
- Ответы на запрос кода одинаковы для существующих и новых номеров.
- Удаление аккаунта анонимизирует персональные данные, заказы остаются обезличенными.

## 10. Вне объёма
Мобильные экраны входа (E07.03), реальные ключи Google, Facebook, Vonage (подключаются позже).
