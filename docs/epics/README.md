# Эпики

Один файл на эпик: `E<этап><номер>-<короткое-имя>.md`. Файл начинается с YAML front matter, из которого инструмент прогресса собирает `docs/progress/plan.yaml` командой `progress sync`. Ручная правка `plan.yaml` запрещена.

## Формат блока задач

Задачи описываются в теле эпика в блоке ```` ```yaml ```` с ключом `tasks:` (под заголовком `## Задачи`). Из таких блоков `progress sync` собирает `docs/progress/plan.yaml`.

```yaml
tasks:
  - id: E00.01.01
    title: "Инициализировать рабочее пространство"
    scope: root/workspace      # rootScope/moduleScope для коммитов
    weight: 2                  # 1, 2, 3, 5, 8
    deps: []                   # id задач
    type: task                 # необязательно: task (по умолчанию) | gate
    acceptance:
      - cmd: nx graph --file=tmp/graph.json
```

Строка вверху файла: `Этап: <M>. Зависимости: <id эпиков>.`

## Разделы тела эпика

1. Цель.
2. Требования (что именно построить, с полями и правилами).
3. Сценарии и состояния (для эпиков с логикой).
4. Контракты и API (если есть).
5. Права, аудит, события.
6. Уведомления.
7. Ключи i18n (префиксы).
8. Угрозы и меры (STRIDE кратко).
9. Критерии приёмки.
10. Вне объёма.

Разделы, неприменимые к эпику, помечаются «н/п». Сквозные требования из `docs/05-cross-cutting-requirements.md` действуют всегда.

## Нумерация задач

`E<этап><эпик>.<задача>`. Задача укладывается в один проект Nx и до ~400 измененных строк. Если больше, агент делит её через `progress split`.
